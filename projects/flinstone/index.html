Flinstone Kernel

A portable kernel built from first principles in C and Assembly. Hardware abstraction, filesystems, process control, and device I/O sit behind versioned subsystem contracts so a release can move without silently breaking the last one.

Run the kernel lab

The freestanding x86 kernel lab is published from Bailey-Forbes-Flinstone to GitHub Pages and boots below as a guest window.

Known limitation. The lab needs cross-origin isolation, which some browsers only grant after the page has been visited on its own origin. If the window above reports that it could not attach, open the lab top-level once and come back — the window has a reload button for exactly this.

How it is served. The lab is published over HTTPS and boots from a Cloudflare Worker on first visit; visitors share a chat room backed by a Cloudflare Durable Object, and the guest falls back to a same-origin BroadcastChannel if that hub is unreachable. Guest DNS resolves through same-origin /lab-dns first and only then Cloudflare DoH.

What it is

The public kernel repo opens 28 May 2025 as a C filesystem and shell. The resume dates the project to 2023. The C line grew a versioning machine: version/entries, locked files, and GM=1 promotes onto main.

About 70 versioned contracts cover networking, storage, drivers, diagnostics, and identity. Backward compatibility is explicit — metadata and migration notes, not “we’ll fix the callers.” The 4.x train on that policy runs 4.0.0, 4.0.1, 4.1.x, 4.2.0, 4.3.0, 4.4.0 and 4.5.0 through 4.5.4, after a 2.x/3.x train that installed the versioning itself.

How the system grew

Hosted filesystem, then a machine. February 2026 turns the shell into an OS sketch: ASM memory primitives, Facade/Strategy/Command file management, port I/O drivers, a thread-safe allocator, an embedded x86 VM (disk, timer, paging, snapshots), and an MLQ scheduler with real vs stub driver capabilities on x86-64 and AArch64.

Contracts before more surface. 3.3.0 (12 May) splits audit from command history and documents fs_jail. 4.0.0 (18 May) is the major bump: inheritable P0–P9 bundles (foundations through hardening). 4.1.0 wires identity — SQLite users, PBKDF2, login/su/sudo, elevation. 4.1.1 is a 50-issue hardening sweep. 4.2.0 (19 Jun) is the networking milestone, and the September 4.3–4.5 train takes it to production Wi-Fi, a browser-kernel contract, and a freestanding boot path.

Networking from the metal up. The 4.2.0 .ver file lists netdev, software loopback, Linux TAP, ARP, IPv4 LPM, ICMP, UDP, TCP shims, DNS, DHCPv4, IPv6/NDP, a Wi-Fi station contract, a multi-device chat/file server, and WSL portproxy hosting. Later PRs add 802.11ax, home-SSID join, macvlan LAN identity, and Dragonfly SAE for WPA3.
